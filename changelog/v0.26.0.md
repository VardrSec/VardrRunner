# v0.26.0 — Local secret resolution for VardrGate identities

Released 2026-07-09.

## Summary

VardrGate API authorization tests need real credentials to exercise an endpoint
as different identities — but those secrets should never sit in the backend
database or travel over the wire in a job. This release lets a job carry a
*reference* to a secret and resolves it to the real value locally on the runner,
immediately before handing the test to the `vardrgate` binary.

## Added

### Credential secret references

In a `vardrgate_api_test` job, each identity credential may specify **at most one**
of:

- `value` — a literal (used as-is; convenient for local runs and tests)
- `value_env` — the name of an environment variable read on the runner
- `value_keychain` — an account looked up in the OS keychain (`keychain.get_secret()`)

The handler deep-copies the test case and replaces each reference with the
resolved value before execution. Guarantees:

- A **referenced-but-missing** secret (`value_env` unset, or no keychain entry)
  raises `ConfigError`, so the job fails cleanly instead of running with a blank
  credential — consistent with "never silent skip."
- Specifying more than one source for a credential is a `ConfigError`.
- Literal `value` and anonymous (empty) credentials are left untouched.
- The backend job stores only the reference; the real secret exists on the runner
  for the duration of the run and never appears in the uploaded result (VardrGate
  redacts credential values by construction).

### `keychain.get_secret(account)`

Reads a non-API-key secret from the OS keychain under a dedicated
`vardrrunner-secrets` service, degrading gracefully to `None` when no keyring
backend is present.

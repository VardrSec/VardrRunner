# v0.30.0 — One redactor, in front of everything

**Date:** 2026-08-17

Phase 1b of the enterprise-grade roadmap. Additive; no command, flag or output
format changed on the happy path.

## Problem

The runner handles a `vmap_` API key, `Authorization` headers, and — since
v0.26.0 — VardrGate identity credentials resolved from environment variables and
the OS keychain. It had **no redaction anywhere**. Three paths carried whatever
they were given straight across a trust boundary:

- **Job events** (`_emit`) are posted to the backend and rendered in its
  Terminal. Whatever text a handler passed went out verbatim.
- **Failure reasons** (`_fail_job`) are printed to the terminal *and* written to
  the backend as `error_message`. Failure messages routinely quote the command,
  URL or payload that failed — precisely where a credential ends up.
- **Daemon poll errors** are printed and, with `--log-file`, persisted to disk.

Nothing had leaked that I could find, but the absence of a leak was luck rather
than design: a `requests` exception carrying a URL with `?api_key=…`, or a tool
error quoting its own argv, would have gone out in full.

## Solution

`redaction.py` is the single layer, and everything crossing a boundary passes
through it. It defends on two independent axes, because either alone has a gap:

**By key name** — `api_key`, `authorization`, `cookie`, `token`, `password`,
`secret`, `private_key`, `value_env`, `value_keychain` and friends, matched as
substrings after normalising hyphens and spaces to underscores. That last part
matters: a first cut missed `X-API-KEY` entirely, because lowercased it is
`x-api-key` and matches neither `api_key` nor `apikey`. The test suite caught it,
which is the argument for writing the adversarial cases first.

**By value pattern** — for free text where there is no key to inspect: `vmap_`
keys, `Bearer`/`Basic` headers, `Cookie:` headers, secret query parameters, and
`key=value`/`key: value` assignments.

Plus two specialists: `redact_url()` for `https://user:pass@host` userinfo,
which no value pattern catches because the secret has no key beside it, and
`redact_exception()` for the common case of logging a failure.

### Properties it guarantees

- **Deterministic.** Same input, same output, no salt — redacted records stay
  comparable and tests can assert exact strings.
- **Idempotent.** Redacting twice is redacting once.
- **Depth-bounded** at 12 levels. Backend payloads are untrusted and could be
  deeply nested; sanitization must not become a DoS on the runner itself.
  Beyond the bound a subtree is replaced with a marker, never emitted unchecked.
- **Never raises.** Sanitizing must not be why a job dies.
- **Non-mutating.** The caller's structure is left intact.

## What this is not

It is **not** a guarantee that a secret never reaches disk. A tool's own output
file is written by that tool, and VardrRunner does not rewrite artifacts in
place. This layer governs what the *runner* emits about them — events, logs,
errors, and (from the journal onward) manifests and audit exports.

## Tests

588 tests (was 540), coverage 95.83%. `redaction.py` at 98%.

`tests/test_redaction.py` is deliberately adversarial — eleven secret shapes in
free text, fifteen sensitive key spellings, nested dict/list payloads, a
60-level hostile nest, non-mutation, determinism and idempotence. Four
boundary tests assert the layer is actually *wired in*, not merely present: job
events, failure reasons reaching both terminal and backend, sanitized logging
when an event post fails, and an unclassified claim failure.

## Known limitations

- Tool artifacts on disk are not rewritten; only what the runner emits about them
  is sanitized.
- Pattern matching is heuristic. A secret with no recognisable key, prefix or
  delimiter — a bare high-entropy string in prose — is not detectable and will
  pass through. Key-name masking is the reliable half; value patterns are
  defence in depth.
- Not yet applied to run manifests or audit exports, which do not exist until
  Phase 2. They will be written through this layer from the start.

# VardrRunner v0.47.0 — API assessments and identity preflight

Released 2026-10-14. Requires Python 3.10 or newer. Install or upgrade with
`pipx install vardrrunner` / `pipx upgrade vardrrunner`, or
`python -m pip install --upgrade vardrrunner==0.47.0`. MCP remains opt-in with
`vardrrunner[mcp]`.

## Identity/session preflight

Reviewed Gate cases may declare a same-origin GET session check on each
authenticated identity. Match public subject/tenant/role metadata; secrets
remain local `value_env` or `value_keychain` references. Install
[Gate v0.1.0 or newer](https://github.com/VardrSec/VardrGate/releases) on the
worker's `PATH`. Gate is not included in the Python package or managed tool manifest.

Runner passes `--require-identity-preflight` for these cases. An older Gate
binary rejects the flag before target traffic. Runner validates the process
exit code and every declared diagnostic together; missing, duplicate or
contradictory reports fail the job. Failed checks must have no authorization
executions or findings. Their safe artifact is uploaded before the job fails,
and recovery preserves the failed finalization even during a backend outage.
Cases without preflight preserve their existing exit-code behavior.

This checks sessions at one moment; it adds no login, refresh or retry behavior.
Deploy the matching Map backend and upgrade both companions before enabling
preflight cases. See [CLI reference](../docs/cli.md).

## Shared guidance and bound assessments

MCP reads Map's original versioned API playbooks and filtered execution evidence.
`api_playbook` is the sixth instruction-only prompt. Human case review, retest
recording and client handoff remain operator decisions; guides infer no coverage.
Playbooks and evidence reads require a full-scope key and matching Map endpoints.

The worker rejects cases changed between polling and claim. Gate artifacts
carry a canonical SHA-256 of the unresolved reviewed spec, retained through
recovery. Resolved credentials are excluded. Map evaluates the claim-time
snapshot; legacy/unbound results remain inconclusive. Binding is correlation,
not signed attestation or proof that an API is secure.

## Queue compatibility and local private targets

Queued legacy `program_id` is normalized to `engagement_id`; conflicting IDs
are rejected. Gate `config.timeout` applies to execution and the subprocess,
and conflicting timeout declarations are refused.

`VARDRRUNNER_ALLOW_PRIVATE_TARGETS=1` locally enables Gate private targets for
internal engagements. Backend job config cannot enable this opt-in. Defaults
remain blocked; this changes Gate's network safeguard, not Map's advisory scope
policy or its enforced stop-work switch.

Documentation and contributor guidance are refreshed. Published artifacts carry
the existing provenance attestation and SBOM; verification covers the supported
Python/OS matrix and disposable three-product HTTP fixtures. Hosted OAuth and
production credentials are outside those fixtures.

# v0.35.0 — Guided setup and host lifecycle hardening

Phase 5 turns the hardened runner components into one safe onboarding path.

## Guided setup

`vardrrunner init` configures or reuses authentication, creates the stable identity and
execution journal, optionally installs the native per-user service, and runs `doctor` as
the final acceptance gate. Interactive setup uses a hidden key prompt and asks for the
runner label/service decision. `--non-interactive` never prompts and fails when required
inputs are absent, making it suitable for repeatable host provisioning.

The command does not weaken login policy: cleartext key storage still requires the literal
`--allow-plaintext-credentials` flag, and a production setup passes only when the strict
doctor profile—including supervision—passes.

## Lifecycle hardening

- Config writes are atomic and permission-restricted.
- Daemon PID creation is exclusive, durable, and owner-restricted where POSIX modes apply.
- Poll and heartbeat intervals have guarded ranges.
- Native service installation refuses shell-only credentials unless a Linux environment
  file is explicitly attached; the service therefore does not appear installed while being
  unable to authenticate after restart.
- Partial keychain login is rolled back if URL persistence fails.

No backend migration or runtime dependency is required. Existing individual `login`,
`identity`, `service`, and `doctor` commands remain available for advanced workflows.

# v0.36.1 — Concurrent execution and release hardening

**Date:** 2026-08-21

Patch release focused on the failure modes that matter on a small team's unattended
runner: concurrent work, graceful shutdown, runaway child processes, local secret residue,
and release-pipeline privilege.

## Runtime reliability

- Run directories are allocated atomically with a timestamp prefix and random suffix.
  Two jobs beginning in the same second can no longer write into the same directory.
- Every tool starts in a dedicated process group/session. A timeout terminates the full
  process tree with `taskkill /T /F` on Windows or the process group on POSIX, then reaps
  the parent.
- Daemon shutdown remains cooperative. The active job may finish cleanly, but the worker
  checks the shutdown signal before each subsequent job and claims no new work.

## Target safety and terminal output

Queue resolution now defers shape validation and local target policy to the journal-aware
job lifecycle. That lifecycle records input statistics before local deny filtering and
screens each target once, preserving duplicate/blank counts while avoiding duplicate
warnings and events. Tool-specific host normalization still de-duplicates after URLs are
reduced to hostnames.

All target finding text is escaped before Rich rendering, so an untrusted value containing
markup-like brackets is displayed literally rather than interpreted as console markup.

## Sensitive VardrGate job data

Resolved VardrGate job envelopes must briefly cross a file boundary because the VardrGate
CLI accepts `--job <path>`. VardrRunner now creates that file exclusively inside a private
temporary directory (mode `0700` with a `0600` file on POSIX), removes the directory after
the run, and fails the successful job closed if cleanup cannot be confirmed. Each CLI
startup also removes abandoned, runner-owned directories whose recorded process is no
longer alive. Symlinks, junctions, malformed names, and active-process directories are
never traversed or removed.

## Release supply chain

- All third-party actions are pinned to immutable commit SHAs.
- Package metadata uses the SPDX `MIT` expression and an explicit license-file declaration.
- The release workflow verifies formatting, types, security, tests, coverage, dependencies,
  and exact tag/package-version agreement before building.
- Build, provenance attestation, GitHub Release, and PyPI publishing are separate jobs with
  only the permissions each job needs. PyPI continues to use OIDC trusted publishing.
- CI now runs Linux tests on Python 3.10 through 3.14 and OS-sensitive smoke coverage on
  Python 3.14 for Windows and macOS.
- `SECURITY.md` documents private vulnerability reporting.

## Verification

888 hermetic tests pass with 95.24% coverage. Ruff lint and formatting, mypy, Bandit, and
the package build checks are clean.

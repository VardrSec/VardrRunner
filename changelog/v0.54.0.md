# VardrRunner v0.54.0 — credential isolation and the native Gau exclusion

Released 2026-10-30. Requires Python 3.10 or newer.

This is a security release. It changes how VardrGate jobs obtain credentials, which tool
processes can see your environment, and how Gau runs. Two changes are breaking; read
**Upgrading** before running queued VardrGate jobs.

## Security

- **Native Gau is excluded.** The upstream Gau 2.2.4 archive disables TLS verification for
  its URL providers, so a network attacker could read or alter provider traffic. 0.53.0 and
  earlier install and run it. `tools install gau` is now refused, `tools install --all`
  skips it, and `run gau` runs only the reviewed container source build, which verifies
  provider certificates and fails on provider errors (ADR 0021).
- **VardrGate credential references need operator approval.** A `vardrgate_api_test` case
  comes from the backend and names the environment variable (`value_env`) or keychain
  account (`value_keychain`) each identity's secret lives in. Earlier releases resolved any
  name, so a case could pick up an unrelated secret, including `VARDRMAP_API_KEY`, and send
  it to a target of its author's choosing. A reference now resolves only when you approved
  it on this machine for the job's engagement and every origin the case contacts. A case
  containing `${...}` is refused, credential targets need a fixed host and port, and Gate
  runs the resolved job with `--literal-job` so nothing is expanded again (ADR 0023).
- **Tools receive an allowlisted environment.** Every tool process, including VardrGate and
  version probes, gets `PATH`, home, temp, locale, XDG, CA-bundle and proxy variables, plus
  the variables Windows programs need. `VARDRMAP_API_KEY`, identity tokens and unrelated
  variables no longer reach tool processes (ADR 0022).

## Upgrading

1. **Install a VardrGate build with `run --literal-job`** (VardrGate ADR 0028) on your
   `PATH`. An older Gate rejects the flag before sending any request, so every
   `vardrgate_api_test` job fails until Gate is updated.
2. **Approve each credential reference your cases use**, per engagement and target origin:

   ```bash
   vardrrunner credentials approve --engagement <id> --origin https://api.example.com --env OWNER_TOKEN
   vardrrunner credentials approvals
   ```

   An unapproved job fails before it is claimed, and the failure names the exact command.
   Approvals store names only, in the owner-only config file.
3. **Native Gau users** switch to the [container toolkit](../docs/container.md).
4. A tool option that was supplied only through an environment variable outside the
   allowlist no longer reaches the tool; use the tool's configuration file instead.

## Container toolkit

Development container and tool-enabled target (Gate, nmap/libpcap and verified managed
tools), with recorded source builds and patched dependencies for Katana, DNSx, Naabu,
httpx, Subfinder, FFUF, Nuclei (go-jose 4.1.6) and Gau. A report-only `govulncheck` step
covers the shipped Go binaries. The container is a development build; no image is published.
See the [container notes](unreleased-container.md) and the per-tool notes linked from
[CHANGELOG.md](../CHANGELOG.md).

## Also in this release

- `doctor --platform` checks Map's `/ready` database and migration contract, and
  `doctor --offline` skips release discovery (ADR 0018).
- Independent Gate write-verifier credentials are resolved locally and their preflight is
  validated with the callers' diagnostics.

**Requires** VardrMap ≥ v0.22.0 as the backend. `doctor --platform` requires a Map that
implements its readiness contract.

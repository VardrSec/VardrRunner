# v0.38.0 — katana and gau

**Date:** 2026-10-08

Adds two discovery tools and fixes a stdin hang that affected every tool. Requires a
VardrMap version that accepts the `katana` and `gau` job types and import formats; nothing
else changes for existing tools.

## katana — crawler

```bash
vardrrunner run katana --engagement <id> --from-recon --depth 3 --js-crawl
```

Crawls each target URL, staying on its root domain (katana's default field scope), and
uploads every endpoint it finds as a recon item. With `--js-crawl` it also pulls endpoints
out of JavaScript files.

katana writes the complete raw request and response, bodies included, on every result
line. The handler keeps only the endpoint and response metadata (method, status, content
length, content type) and de-duplicates by method and URL before uploading. That keeps
uploads small and keeps page content the operator never asked to store out of VardrMap.

The output format was taken from real katana 1.8.0 runs against a local test server, not
from documentation.

## gau — archived URLs

```bash
vardrrunner run gau --engagement <id> --providers otx,wayback
```

Passive. gau asks public archives (Wayback Machine, Common Crawl, AlienVault OTX, urlscan)
which URLs they have recorded under each wildcard scope domain; nothing is sent to the
target. It takes the same targets as subfinder, and the two share one helper for reading
wildcard scope. gau receives domains as arguments, always after `--`.

Archives for popular domains are large and the Wayback Machine can be slow; long gau runs
are bounded by the normal tool timeout.

## Large results

VardrMap refuses imports over 2 MiB by default (`MAX_UPLOAD_BYTES`), and gau on a
well-known domain returns tens of thousands of URLs. katana and gau results are uploaded
in line-aligned pieces of at most 1.5 MB; anything that fits goes up as a single file
exactly as before. Piece files are removed even if an upload fails partway. VardrMap
v0.37.0 de-duplicates URL recon within an upload as well as against stored rows, which is
what makes splitting safe.

## Installer

katana 1.8.0 and gau 2.2.4 are pinned for Windows, Linux, and macOS (amd64 and arm64). All
ten archives were hashed locally and matched each project's published checksums, and
re-pinning left every existing pin byte-identical.

gau ships `.tar.gz` archives on Linux and macOS, so the installer now reads tar.gz. It keeps
the zip guarantees: only the one expected member is read, and only if it is a regular file.
Symlinks, hardlinks, directories, and device entries are refused, and the size cap applies
to the bytes actually read. Each tool can also declare its own version flag (gau uses
`--version`); the manifest validator accepts only bare options.

## Fixed: tools hanging on stdin

Testing katana from a background shell, it ran indefinitely with no output. ProjectDiscovery
tools read extra targets from stdin whenever stdin is not a terminal, and VardrRunner started
tools with the caller's stdin. With an open pipe that never closes (a script, supervisor, or
CI job), the tool waits forever. This affected httpx, nuclei, subfinder, dnsx, and naabu as
well as katana. Tools, and the version checks in `status`, `doctor`, and the installer, now
always run with an empty stdin. Targets always arrive in files or arguments, so no tool
needs it.

## Tests

1026 tests (53 new), coverage 95.87%. `tests/test_katana_gau.py` covers configs and their
bounds, argv construction, katana body stripping and de-duplication against a captured
real result line, gau normalization, tar.gz installs (including refusing link and
directory entries), and an invariant that every tool the installer can install is also
allowlisted and has a handler. CLI tests assert the exact keyword arguments of `run katana`
and `run gau`.

## Not in this release

- No pipeline uses katana or gau yet; they run as individual jobs.
- `import katana` / `import gau` for existing files are not added.

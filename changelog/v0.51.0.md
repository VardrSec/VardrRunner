# VardrRunner v0.51.0 — interactive console; legacy commands removed

Released 2026-10-24. Requires Python 3.10 or newer. No VardrMap change is required.
**Breaking:** the `daemon` and `service` commands, the hidden `init` service options and
`engagement-list` are removed (see below).

Upgrade with:

```text
vardrrunner update
```

From 0.50.0, this is the first release `vardrrunner update` can install by itself.

## Interactive console

### Type commands without `vardrrunner`

```text
PS> vardrrunner
 .::::::::::::::::::::::.    VardrRunner 0.51.0
 ::                    ::    A product of VardrSec · https://www.vardrsec.com
 ...
vardrrunner > heartbeat
vardrrunner > use 3f2a9c1e-…
vardrrunner(3f2a9c1e) > scope
vardrrunner(3f2a9c1e) > jobs run
vardrrunner(3f2a9c1e) > exit
```

- **Bare `vardrrunner` at a terminal** opens the console. Every command and flag works as
  it does on the command line. Bare `vardrrunner` in a script or pipe still prints help and
  exits 2.
- **`use <engagement-id>`** fills in `--engagement` (and the ID `scope` takes) for every
  command until `back`. An engagement typed on the line still wins.
- **Console commands:** `help` or `?`, `use`, `back`, `banner`, and `exit`, `quit` or
  Ctrl+D.
- **Errors keep the console open.** Ctrl+C cancels the running command, not the console.
- **`mcp` can't run inside the console.** Run `vardrrunner mcp` from your shell.
- **After `update`,** if a newer version was installed, the console says so and closes. Run
  `vardrrunner` to reopen it on the new version.

### Banner

The VardrSec shield, the version, tool, pipeline and job-type counts, the VardrMap host,
a cached update notice, a quote and a tip. Opening the console makes no network request
and never reads the API key. Quotes without a primary source are credited "attributed to".

### Tab completion (optional)

```text
pipx install --force 'vardrrunner[shell]'
# or, on an existing pipx install:
pipx inject vardrrunner prompt_toolkit
```

This adds completion for commands, subcommands and options, plus up-arrow history. History
is kept in memory only, so a key typed on the line is never written to disk.

See [ADR 0017](../docs/adr/0017-interactive-console.md).

## Legacy daemon and service commands removed (breaking)

### Removed

| Removed | Now |
|---|---|
| `vardrrunner daemon start\|stop\|status` | `No such command 'daemon'` |
| `vardrrunner service install\|uninstall\|status` | `No such command 'service'` |
| `vardrrunner init --install-service`, `--start-service`, `--no-start-service`, `--env-file` | `No such option` (exit 2) |
| `vardrrunner engagement-list` | use `vardrrunner engagements` |

Since 0.48.0 none of these could start work (ADR 0016). They existed only to clean up
installs from 0.47.0 or earlier. `doctor` also drops its `daemon` check.

### If you still have a startup service from 0.47.0 or earlier

Upgrading does not remove it. Remove it once by hand:

| OS | Command |
|---|---|
| Windows | `schtasks /End /TN VardrRunner` then `schtasks /Delete /TN VardrRunner /F` |
| Linux | `systemctl --user disable --now vardrrunner.service`, delete `~/.config/systemd/user/vardrrunner.service`, then `systemctl --user daemon-reload` |
| macOS | `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.vardrsec.vardrrunner.plist`, then delete the plist |

The leftover files `~/.vardrrunner.pid`, `~/.vardrrunner.log` and `~/.vardrmap/daemon.jsonl`
can be deleted.

### Stop-work in `jobs run`

When stop-work refuses a claim, the run skips that engagement's remaining jobs and prints
"Skipping this engagement's remaining jobs in this run." Other engagements still run. The
old message promised a 60-second recheck, which only the removed daemon ever did. The next
`jobs run` asks the backend again.

See the [ADR 0016 amendment](../docs/adr/0016-explicit-daemon-execution.md).

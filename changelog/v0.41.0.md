# v0.41.0 — Job-linked uploads, case authoring, correct MCP paging

**Date:** 2026-10-09

Pairs with VardrMap v0.39.0 (engagement delivery workflows) and **requires it** for the MCP reads
and for the job validation described below. First drafted by OpenAI Codex, then reviewed, tested and
documented.

## Uploads name their job

VardrMap now records, per job, every recon, scan and service row the job *observed* - including
rows an earlier job created, which de-duplication used to hide. To do that the backend needs to know
which job an upload belongs to, and it now validates the id against the engagement's own jobs.

Every handler's upload therefore passes `job_id`: httpx, nuclei, subfinder, dnsx and the katana/gau
chunked uploads on `POST /imports`, and nmap/naabu on `POST /services`. Direct `vardrrunner run ...`
commands have no job and send none, exactly as before, so older backends and existing scripts are
unaffected. A backend that predates v0.39.0 simply ignores the extra field.

## `vardrrunner test-cases`

```bash
vardrrunner test-cases draft <engagement> --output review.json --endpoint <id> --endpoint <id>
vardrrunner test-cases draft <engagement> --output review.json --openapi api.json --base-url https://api.example.test
vardrrunner test-cases save  <engagement> --file review.json --reviewed
```

Authoring VardrGate authorization cases by hand is the slow part of broken-access-control testing.
`draft` asks VardrMap to generate cases from observed API operations or an OpenAPI 3.x document and
writes them to a review file. The design assumes the draft is a starting point, not an answer:

- The output path must not exist, so a draft you are part-way through editing is never overwritten.
- A draft containing a literal credential is refused and no file is written. Identities use
  `value_env` / `value_keychain` references that this runner resolves locally at run time.
- Every access decision starts as `skip`. Observed responses show what an API *does*, not who
  *should* have access, so a draft never guesses.
- `save` needs `--reviewed`, a deliberate confirmation that you checked targets, identities and
  decisions. It accepts the file `draft` wrote or a bare JSON array, and tolerates a UTF-8 BOM
  (PowerShell's `>` writes one). Nothing is queued.

## MCP reads page correctly

The v0.40.0 MCP server fetched one page and then filtered it. `list_findings(severity="high")` only
looked at the first page of findings, so high-severity findings beyond it were missed, and the
reported total was the page size or the unfiltered total rather than the number of matches. The same
flaw affected `list_recon(source=...)` and `list_jobs(status=...)`.

Filters and an `offset` now go to VardrMap, which filters before paging and returns the matching
total. Each result carries `count`, `offset`, `limit`, and `next_offset` (`null` on the last page), and
the tool descriptions tell the agent to follow `next_offset`. An older backend that cannot report a
total now produces a clear "requires VardrMap v0.39.0" error rather than a plausible-looking wrong
answer. Backend error text and the "not configured" message go through the redactor, and the login
hint is no longer printed twice.

## Tests

1122 tests, coverage 95.99%. New: `tests/test_upload_provenance.py` (every tool's upload carries the
job id; none is sent without a job; every chunk of a large result carries it),
`tests/test_test_cases_command.py` (never overwrites the review file, refuses literal credentials,
requires `--reviewed`, BOM and bare-list input, server refusals), and CLI wiring tests asserting the
exact arguments and the out-of-range paging values (`--limit 0`, `101`, `--offset -1`).

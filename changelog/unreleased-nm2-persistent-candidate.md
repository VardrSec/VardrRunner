# Inactive persistent managed worker candidate

Add explicitly selected persistent-v3 admission and an additive worker image.
Nonspawning idle has no default timeout or job-count limit; operators can select
finite controls. Every job still needs fresh authority, approved credentials,
budgets and finite lease/hard deadlines. Exact int64 epochs, normal native return,
empty lineage, a sealed and joined Control thread, durable terminal completion
and original-token release precede another claim. A failed/rejected refresh
permanently denies v3 reuse without changing legacy active-lease behavior.

Legacy finite images and wire formats remain supported. This candidate requires
the matching Map persistent runtime endpoints and journal/protocol cohort. It
remains inactive: the proposed STOP-only reporting lifetime needs an explicit
owner disposition, and supported-platform plus retained security acceptance is
still required. Pure tests establish component behavior, not containment or
platform acceptance.

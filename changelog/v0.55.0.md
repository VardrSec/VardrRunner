# VardrRunner v0.55.0 — workspaces and controlled execution

**Status: source version prepared, not published.** These notes assign the changes
since 0.54.0 to version 0.55.0. They do not announce a release date or the availability
of a PyPI package, downloadable binary or container image. Requires Python 3.10 or newer.

## Capabilities

- Standalone workspaces, reviewed Gate cases, portable evidence exports and bounded
  DNS/HTTPS Recon through the matching Full or Mapless distribution.
- Finite authorization, expiring credential grants, controlled cancellation,
  target/duration budgets and concurrency controls.
- Explicitly enabled managed workers with durable journals and authenticated
  original-run reconciliation. Unknown work remains held.
- Review-only Gate drafts, operator-approved queue proposals and redacted provenance
  in exports.

## Security and packaging

- Preserve hash-verified tool installation and binary integrity checks; protect
  agent-local credentials and make required release SBOM failures visible.
- Upgrade runtime security packages and rebuild toolkit libpcap 1.10.7 to address
  unsafe BPF memory access and unbounded jumps, retaining source and notices.
- Require the reviewed, license-corrected LDAP dependency in the Nuclei source build
  and record its build provenance.
- Retain managed-tool notices, downloaded Go-module legal texts and the Go license
  alongside hashed source-build provenance. Retain Gate's license in the toolkit.
- Include Dalfox dependency notices, locked source references and four unmodified
  MPL dependency sources as inert package data without changing tool binaries.

## Choose your setup path

Use the matching VardrSec distribution rather than treating component development
containers as a separate integrated installation:

- **Full:** follow the [Full installation guide](https://github.com/VardrSec/VardrSec/blob/main/docs/installation.md).
- **Mapless:** follow the [Mapless guide](https://github.com/VardrSec/VardrSec/blob/main/docs/mapless.md).

The [CLI reference](../docs/cli.md), [container guide](../docs/container.md) and
[limitations](../docs/limitations.md) distinguish manual, direct and controlled use.

## Operating limits

- Creating workspace metadata does not authorize or start execution. Review and
  authorization remain separate steps.
- Managed workers are opt-in, not enabled by the version change.
- An ordinary Linux/Docker invocation without a live native lifecycle-owner context
  cannot run the controlled standalone lane. Use the distribution's documented
  `runner --controlled` adapter for that path.
- Manual/direct scope and engagement-window warnings are advisory; they must not be
  mistaken for the signed controlled lane's enforcement. Local restrictions and
  stop-work checks still apply.
- The native Gau exclusion and operator-approved Gate credential references from
  [0.54.0](v0.54.0.md) remain in effect. This version assignment does not relax them.

# VardrRunner v0.50.0 — `vardrrunner update`

Released 2026-10-24. Requires Python 3.10 or newer. Upgrade once more by hand with
`pipx upgrade vardrrunner`; from this release on, `vardrrunner update` does it. No VardrMap
change is required.

## Update in one command

```text
PS> vardrrunner update
Updating VardrRunner 0.50.0 → 0.51.0…
Updated to VardrRunner 0.51.0.
```

- **pipx installs** (the documented install): `update` runs `pipx upgrade vardrrunner` in the
  foreground, then confirms the new version from a fresh, isolated interpreter. It reports
  success only when that version is installed; otherwise it shows the installer's output and
  exits non-zero. Packages added with `pipx inject`, such as the `mcp` extra, are kept.
- **uv or a plain virtualenv**: `update` prints `uv tool upgrade vardrrunner` or
  `python -m pip install --upgrade vardrrunner` and exits 1. pip would have to replace the
  running `vardrrunner.exe`.
- When the install is current: `Up to date. VardrRunner 0.50.0`, and nothing is run.

Nothing updates on its own; only typing `vardrrunner update` installs anything (ADR 0012
amendment).

## Doctor says when an update exists

`doctor` opens with a `version` line. A newer release is a warning:

```text
! version: 0.50.0, update available: 0.51.0
    → Run `vardrrunner update`.
```

It asks PyPI every time (5-second timeout). If PyPI can't be reached the line is OK and says
the check could not run, so doctor never fails because of it.

## Always-fresh checks

`update check` used a 24-hour cache, so it could say "Up to date" for hours after a release.
`update`, `update check` and `doctor` now always ask PyPI and refresh the cache that `status`
and `--version` read. `update check --force` still works and does nothing extra. Update
notices everywhere now say `Run vardrrunner update`.

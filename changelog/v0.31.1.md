# v0.31.1 — Phase 1 integration hardening

**Date:** 2026-08-18

Patch release completing the security and availability behavior introduced in
v0.29.0–v0.31.0.

## What changed

- Stop-work blocks when returned as HTTP 403 or as a `stop_work_active` warning.
- The daemon suppresses repeated stop-work claims for 60 seconds, then rechecks so
  lifting the halt resumes work without restarting the daemon.
- Credential posture inspection handles corrupt and unreadable config files without
  reparsing them through helper functions.
- Secret redaction and Rich-markup escaping now cover every existing operator/backend
  output path, including job configuration listings, policy messages, direct runs,
  pipelines, status, doctor, heartbeat, keychain diagnostics, engagement metadata and
  scope values.

## Compatibility

No backend change is required. Existing commands and configuration remain compatible.
The stop-work recheck interval is intentionally local and does not alter backend policy.

## Tests

Added integration coverage for stop-work warnings, automatic stop-work recovery,
corrupt-config inspection without mocked reparsing, and Rich-safe redaction. The full
suite remains above the 95% coverage floor.

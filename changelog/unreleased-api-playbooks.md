# Shared API playbooks and execution binding (unreleased)

Three read tools add the shared catalog, guide detail and paginated execution
provenance. api_playbook is a sixth instruction-only prompt. Human case review,
retest recording and client handoff remain operator decisions. Map must deploy
its matching endpoints and assessment migration first.

The worker refuses a case changed between polling and claim. Gate artifacts
carry a canonical hash of the unresolved reviewed spec so Map can distinguish
bound assessments from legacy/unknown results. Recovery keeps the same artifact
and hash; credentials are resolved locally and are not included in the binding.
This is correlation, not a cryptographic attestation or full coverage claim.

# v0.27.0 — Programs are Engagements

Released 2026-08-04.

## Summary

VardrMap renamed its core entity from *program* to *engagement* when it widened
from bug bounty work to professional security testing. This release follows that
rename so the two halves of the toolchain use the same word for the same thing.

**Requires VardrMap ≥ v0.21.0.** The runner now calls `/engagements/*`, which
older backends do not serve. Deploy VardrMap first, then upgrade the runner.
The reverse order is safe to *skip*, not to perform: a v0.21 backend still
answers the old `/programs/*` paths, so an un-upgraded runner keeps working
indefinitely.

## Changed

- `api.py` calls `/engagements/*` instead of `/programs/*`. `VardrMapClient`
  methods renamed: `programs()` → `engagements()`, `program()` → `engagement()`.
  Every `program_id` argument is now `engagement_id`.
- The engagement list reads the `engagements` response key and falls back to
  `programs`, so it works across the transition.
- `commands/programs.py` → `commands/engagements.py`.
- Docs and help text say "engagement" throughout.

## Compatibility

Nothing an operator types has to change:

- **`--program` still works.** Every command accepting `--engagement` also
  accepts `--program` and `-p`, unchanged.
- **`vardrrunner programs` still works.** It is hidden from `--help` so only the
  current name is advertised, but the command still runs.

These aliases exist so upgrading the runner never breaks a script or a habit.
They can be retired once nothing is calling them.

Note that *program* keeps its own, different meaning in VardrMap: a bug bounty
programme on HackerOne or Bugcrowd, as listed by Target Radar. Those were not
renamed, in either repository.

## Tests

439 passing, unchanged from v0.26.0 — the rename is behaviour-preserving.

# v0.42.0 — MCP prompts

**Date:** 2026-10-09

The four workflows an operator repeats on every engagement, as MCP prompts. Decision
record: [ADR 0015 § Amendment (v0.42.0)](../docs/adr/0015-mcp-server.md).

## What they are

```
/mcp__vardr__brief       engagement_id
/mcp__vardr__triage      engagement_id  [severity]
/mcp__vardr__untested    engagement_id
/mcp__vardr__retest      engagement_id  [finding_id]
```

MCP prompts are how a client turns a server's workflows into slash commands. Nothing
about the tool surface changed — these drive the same read and guarded-write tools
v0.40.0 added.

| Prompt | What it asks for |
|--------|------------------|
| `brief` | Where the engagement stands: type, client, status and authorization window; in and out of scope; which tools have run and what failed; how much recon, assets and API surface exist; findings by severity; which reports exist. Ends with the three things to do next. Queues nothing. |
| `triage` | Pages the whole findings inventory (following `next_offset`, not stopping at page one) and judges each finding on four axes: is it real or a bare template match, does the severity hold given exploitability and exposure, what evidence supports it, and what is the smallest check that would settle it. Groups the result as confirmed / needs-verification / likely false positive. `severity` narrows it. |
| `untested` | Establishes what exists (scope, assets, recon, API operations) against what has run (jobs, failures included), names the gaps concretely — domains never enumerated, hosts never probed, live hosts never crawled, no port scan, archived URLs never probed, API operations with no authorization test — and proposes an ordered plan with `preview_job` counts attached. |
| `retest` | Restates a finding and its asset, picks the narrowest check that proves the fix landed against that one asset, previews and queues it, follows the job to completion, and reports fixed / still present / **inconclusive** — explicitly allowing the third answer instead of rounding it up. `finding_id` targets one; otherwise it finds the findings due a retest and asks which. |

Each takes an optional `engagement_id`. Left blank, the prompt tells the agent to list
the engagements, show them, and ask — never to guess.

## A prompt is instructions, not data

**Expanding a prompt makes no API call and embeds no engagement data.** The obvious
alternative — pre-fetch the findings and paste them into the triage prompt — is the
wrong shape for this server.

Prompt text arrives as the most trusted content in the agent's context. A tool result
does not: the server's `instructions` already frame tool output as untrusted data from
the targets under test. Finding titles, recon URLs, response metadata and scanner
output all originate from those targets, so pasting them into a prompt would launder
target-controlled strings out of the untrusted position and into the trusted one — to
save a single tool call, and at the cost of the framing that bounds the prompt-injection
risk the whole design is built around.

So the agent gathers its own data through the read tools. The prompts stay correct as an
engagement changes, since nothing is baked in at expansion time, and they need no
permission the tools did not already have.

The prompts also state where no tool exists rather than implying one: `triage` cannot
edit a finding, and `retest` cannot record itself against a finding's history, so both
hand the operator exactly what to enter in VardrMap.

## Tests

`tests/test_mcp_server.py` asserts the exact prompt surface, and — per prompt — that
expansion leaves the API client untouched (`fake.mock_calls == []`, the regression guard
for the no-pre-fetch rule), that a blank `engagement_id` produces an ask rather than a
guess, that every prompt marks tool output as data, that the three which can lead to work
require a preview and the operator's approval, and that `brief` names no queue tool at
all. Plus the per-prompt specifics: the `severity` and `finding_id` variants, that
`triage` pages with `next_offset` and claims no finding-edit tool, and that `retest`
keeps "inconclusive" available.

## Not in this release

MCP tools for VardrGate case drafting and report drafting (the backend and CLI exist as
of v0.41.0; the agent cannot reach them yet), methodology checklists, and a remote/hosted
MCP for claude.ai, which would need OAuth on the backend.

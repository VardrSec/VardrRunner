# v0.24.0 — Pipeline planning, machine-readable results, daemon reliability

**Date:** 2026-06-26

Minor release. Two additive `pipeline run` flags plus a set of daemon and logging fixes.
No breaking changes.

## Added

### `pipeline run --dry-run`

Resolves first-stage targets and prints the planned tool chain **without executing any
tool**. Intended for confirming scope and target count before committing to a long run —
particularly useful alongside the 500-target cap, since the dry run shows whether a stage
would trip it.

### `pipeline run --json`

Emits a machine-readable JSON result once the pipeline completes: run ID, per-stage
status / targets / summary / elapsed, and an overall `success` flag. Written for CI
scripts that need to branch on the outcome rather than parse the TUI.

## Fixed

- **Daemon log files no longer contain Rich markup brackets.** The file-mode `Console` was
  constructed with `markup=False`, so `[green]`, `[dim]`, and friends were written
  literally into the log. Dropping the flag lets Rich render markup to plain text, since
  the log file is not a terminal. `_RotatingLogFile` now also implements
  `isatty() → False` explicitly rather than relying on the default.
- **Daemon poll backs off exponentially.** A downed backend was previously retried every
  `poll_interval` seconds no matter how many times it had failed. The daemon now backs off
  5 s → 10 s → 20 s …, capped at 5 minutes, and resets the streak on the next successful
  poll. The error line includes the retry delay so the operator can see it is backing off
  rather than hung.
- **`_extract_jsonl_field` OSError is logged as a warning** instead of silently swallowed,
  so a disk-full or permissions failure during result parsing becomes visible.
- **Collapsed redundant exception handlers in `_run_stage`.** `ToolTimeout` is a subclass
  of `Exception` and both handlers returned the same result shape, so the separate branch
  was dead code.

## Changed

- **`SubfinderHandler.execute()` and `DnsxHandler.execute()` share
  `_write_host_import_jsonl()`.** Both duplicated the same JSONL conversion loop; it is
  now a module-level helper in `handlers.py`.

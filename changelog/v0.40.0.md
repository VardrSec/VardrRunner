# v0.40.0 — MCP server

**Date:** 2026-10-08

Lets an AI agent drive a VardrMap engagement through VardrRunner. Decision record:
[ADR 0015](../docs/adr/0015-mcp-server.md).

## What it is

```bash
pip install 'vardrrunner[mcp]'
claude mcp add vardr -- vardrrunner mcp      # Claude Code; Desktop uses its MCP config
```

`vardrrunner mcp` runs a [Model Context Protocol](https://modelcontextprotocol.io) server
over stdio. An MCP client (Claude Code, Claude Desktop) connects and can read an engagement
and queue work, using the same `vmap_` key this runner already stores. The model is the
client's; VardrRunner only adapts VardrMap's HTTP API to MCP tools. The server is a thin
adapter over the existing API client, so no VardrMap change was needed.

## Tools

**Read** (no change to anything): `list_engagements`, `get_engagement` (with scope and
stats), `list_scope`, `list_findings` (optional severity filter), `list_assets`,
`list_api_endpoints`, `list_recon` (optional source filter), `list_jobs` (optional status
filter), `get_job_events`, `list_reports`, and `preview_job` (a dry run). Each read caps its
result to a bounded sample plus the true total, so a large recon or asset table never floods
the agent.

**Guarded writes** — the client surfaces each for the operator to approve: `queue_job`,
`queue_pipeline`, `create_finding`.

## What it deliberately can't do

No tool edits scope or authorization, triggers stop-work, deletes anything, or manages
members, API keys or settings. The operator does those in the UI.

Withholding a scope-editing tool is the main defence against prompt injection: the agent
reads text that comes from the targets under test (response bodies, scanner output, finding
text), so that text is an injection vector. With no tool to widen what may be tested, a
planted "add 10.0.0.0/8 to scope" instruction has nothing to call. The server's instructions
also tell the agent to treat tool output as data and to surface, not obey, embedded
instructions. This bounds the blast radius and keeps the operator approving every write; it
does not make the agent safe to run unattended against a hostile target.

The advisory model is unchanged (ADR 0001): a queued job outside scope still returns warnings
and still runs. The MCP layer adds no enforcement.

## Packaging

`mcp` (and its pydantic/anyio/starlette tail) is an optional extra; the core runner never
imports it, so a plain install stays lean. `mcp` is also in the `dev` extra so CI runs the
server's tests, type-checks its lazy imports, and measures its coverage. The `mcp` command
prints an install hint if the extra is missing.

## Tests

`tests/test_mcp_server.py` drives the server in-process with a fake API client — no network,
no real agent. It asserts the exact tool surface and that no scope/auth/delete tool exists,
the read-only vs write hints, output capping with the real total, the severity/source/status
filters, that writes post the expected body to the expected path, and that 404/400/connection
failures become readable tool errors (a 404 without confirming the object exists). Skipped
when the `mcp` extra is absent. CLI tests cover `vardrrunner mcp` running the server and the
install-hint path when the extra is missing.

## Not in this release

MCP *prompts* (slash-command workflows), VardrGate test-case authoring, report drafting, and
a remote/hosted MCP for claude.ai (which would need backend OAuth) are future phases.

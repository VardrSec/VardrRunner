# v0.39.0 — Content pipeline and operability polish

**Date:** 2026-10-08

Follows v0.38.0 (katana and gau). Adds a pipeline that uses both, finishes first-run setup,
and fixes two rough edges found while testing the new tools.

## `content` pipeline

```bash
vardrrunner pipeline run content --engagement <id>
```

subfinder → httpx → katana → gau: enumerate subdomains, keep the ones that answer, crawl
those live hosts for endpoints, and add the URLs public archives already hold for the scope
domains. Every stage feeds the recon store. VardrMap's composer offers the same chain as
"Content Discovery".

## `init` installs tools

Guided setup now offers to install the pinned, verified tools, so a new runner finishes able
to scan instead of reporting missing tools at the end. Interactive setup asks (default yes);
`--non-interactive` skips it unless `--install-tools` is passed. A tool that fails to install
(antivirus, an unsupported platform) does not abort setup — the closing `doctor` lists it.

## Managed nuclei templates live under `~/.vardrmap/data`

A managed nuclei is run with `-update-template-dir ~/.vardrmap/data/nuclei-templates`, so the
whole install — binary and templates — sits in one place `tools purge` clears. A nuclei on
your `PATH` is untouched, so it keeps its existing template directory and isn't forced into a
fresh multi-hundred-MB download.

## Fixed: `doctor` crashed on redirected output

`doctor`'s report used `✓`/`✗`/`→`/`—`. On Windows, output sent to a pipe or file uses the
legacy code page, which can't encode those, so `vardrrunner doctor > report.txt` aborted part
way through. The report now degrades to ASCII `OK`/`WARN`/`FAIL` when a stream can't show the
symbols, and the CLI reconfigures such streams to replace unencodable characters instead of
raising. Real consoles and UTF-8 streams are unchanged.

## Tests

`tests/test_cli.py` covers the output-stream hardening and the `init --install-tools` wiring;
`tests/test_doctor.py` the ASCII fallback; `tests/test_runner.py` that a managed nuclei gets
the template-dir flag while a `PATH` nuclei does not; `tests/test_setup.py` the tool-install
step (offered interactively, skipped unattended, non-fatal on failure); `tests/test_pipelines.py`
the `content` chain and that every pipeline stage is a registered tool.

# v0.22.2 — Observability in the silent paths

**Date:** 2026-06-20

Maintenance release. No new commands, no flag changes, no behaviour change for a healthy
runner — this release is about what happens when something goes wrong quietly.

## Problem

Several code paths were deliberately silent so that quiet/daemon operation stayed quiet,
and they had become silent about real failures too:

- `_emit()` in `jobs.py`, `heartbeat.py` in quiet mode, and the daemon all swallowed
  exceptions. A job whose lifecycle events never reached the backend looked identical to
  one that reported normally — the backend Terminal simply showed nothing.
- An invalid `VARDRRUNNER_TOOL_TIMEOUT` was ignored without comment, so an operator who
  typed `30m` instead of `1800` silently got the default.
- `keychain.py` returned `None`/`False` on any exception, which is correct behaviour
  (degrade gracefully) but left no way to tell "no keyring backend installed" apart from
  "the keyring backend is broken".

## Solution

Log instead of swallow, at the severity the situation deserves:

- **`logging.warning()`** on failed event emission, failed quiet heartbeats, and daemon
  errors — visible in log aggregation without breaking quiet operation.
- **`logging.warning()`** on an invalid `VARDRRUNNER_TOOL_TIMEOUT`, naming the bad value
  and the default being used instead.
- **`logging.debug()`** in `keychain.available()`, `get_key()`, `set_key()`, and
  `delete_key()` so keyring backend problems are diagnosable on demand.

## Specifics

- **Handler signatures typed.** Every concrete `ToolHandler` method is annotated with its
  specific config type (e.g. `configs.HttpxConfig`) rather than `Any`, so a
  config/handler mismatch is caught by mypy instead of at runtime.
- **JSONL parsing deduplicated.** `_extract_jsonl_field()` replaces three identical
  implementations across `HttpxHandler`, `SubfinderHandler`, and `DnsxHandler`.

## CI

- **bandit added to the lint job** — `bandit -r vardrrunner -ll -q` blocks merges on
  high/medium severity findings.
- **Coverage floor raised to 95%** (`--cov-fail-under=95`), with new test files covering
  `api.py` HTTP methods, `keychain.py`, `commands/auth.py`, `commands/programs.py`,
  `commands/heartbeat.py`, `cli.py` (via `typer.testing.CliRunner`), and the job
  lifecycle edge cases: malformed job, unknown tool, config error, target-resolution
  failure, claim race, no output, `ToolTimeout`, and generic exception.

# v0.33.0 — Runner operations

Phase 3 makes a VardrRunner host identifiable, observable, and manageable without adding
an external operations platform.

## Operator features

- `vardrrunner identity show` displays the stable installation UUID, label, and hostname.
- `vardrrunner identity set-name <label>` assigns a durable human name;
  `VARDRRUNNER_NAME` provides a non-persistent deployment override.
- `daemon start --log-format json --log-file <path>` writes rotating JSON Lines suitable
  for simple collectors and SIEM agents.
- `service install|status|uninstall` manages a per-user systemd unit, launchd agent, or
  Windows Scheduled Task. `service install --dry-run` previews all host changes.
- `doctor --production` adds strict credential, durable-state, disk, and service checks.

## Compatibility

Heartbeat identity fields are additive. Backends that do not yet store them continue using
hostname identity. Service installation is optional; direct and detached daemon operation
remain supported. No backend migration or new Python dependency is required.

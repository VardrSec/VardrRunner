# v0.23.0 — Live pipeline TUI

**Date:** 2026-06-23

Minor release. `pipeline run` gains a live-updating status table; no flags changed and no
pipeline semantics changed.

## Problem

A pipeline run printed line after line as it went. On a `recon` run — subfinder, then
httpx, then nuclei, each potentially minutes long — the operator could not tell at a
glance which stage was active, how many targets it had picked up, or how long the earlier
stages had taken. Scrollback was the only history, and a stage that was aborted because an
earlier one failed looked the same as one that had not started.

## Solution

Each stage is now a row in a Rich `Live` + `Table` display, updated in place:

- a spinner while the stage is running
- a final status icon: `✓` done, `✗` failed, `⊘` no targets, `—` aborted
- target count, result summary, and elapsed time per stage

When a stage stops the pipeline, every remaining stage is marked aborted immediately
rather than being left blank, so the final table is a complete account of the run.

## Specifics

- `_run_stage()` returns a structured `_StageResult` dataclass instead of printing
  directly. All display logic moved into `_PipelineTUI`, which keeps the runner free of
  presentation concerns and makes the stage outcome testable as data.
- The TUI is display-only: stage ordering, handoff files, and the stop/continue decision
  are unchanged from v0.21.0.
